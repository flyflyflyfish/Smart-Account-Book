# 安全设计（草稿）

> 本项目基于开源项目 `account_app_harmonyos`（作者 banggx，Apache-2.0 许可）二次开发。
> 本文梳理图片识别记账功能的隐私与安全威胁点及对应措施，随阶段迭代持续更新。

## 1. 威胁点与对应措施

| # | 威胁点 | 风险 | 对应措施 |
|---|--------|------|----------|
| T1 | 日志明文泄露账单金额、备注 | 系统日志可被其他调试工具读取，泄露用户财务隐私 | `Logger` 默认使用 `%{private}s`；`DBUtil` 只记录操作类型、数量、耗时，不再打印账单内容、SQL 语句与查询结果 |
| T2 | 日志泄露 API Key、图片数据 | 密钥与图像内容进入日志后难以彻底清除 | `PreferenceUtil` 对含 key/password/secret/token 的键打码后再记录；云端识别不打印 Authorization 头与 base64 图片 |
| T3 | 原图/缩略图残留在本地 | 用户账单照片长期留存，泄露隐私 | 识别全程从系统 picker 返回的 URI 直接读取，**不复制、不落盘**，识别完成不留副本；当前不实现缩略图功能 |
| T4 | 云端上传未经用户知情同意 | 图片被静默上传到第三方服务商 | 首次使用云端识别时弹出说明（图片将上传到已配置的服务商），用户同意后才继续；同意状态存 Preferences（`cloud_consent`），设置页可随时撤回 |
| T5 | 硬编码 Key、地址、路径 | 密钥泄漏进代码库/仓库 | 全项目检查无硬编码 API Key、服务地址、证书路径；API Key 仅由用户在设置页输入、存本机 Preferences，界面打码展示 |
| T6 | 学习到的商家分类映射无法清除 | 用户行为画像数据不可控 | 设置页提供「清除学习到的商家分类」按钮（二次确认后删除 `merchant_category` 全表） |
| T7 | 崩溃日志含敏感信息入库 | jscrash 文件可能包含账单上下文 | `.gitignore` 已忽略 `jscrash-*.txt`；如工作区已生成该文件应删除，不入库 |

## 2. 数据落盘与存储边界

- 账单数据：`account.db`（表 `account`），安全等级 `S1`，仅存本机。
- 商家分类记忆：`account.db`（表 `merchant_category`），仅存本机。
- 云端配置与同意状态：Preferences（库名 `account_store`），仅存本机。
- 图片数据：不落盘，仅在内存中转为 base64 后随请求上传，请求结束即释放。

## 3. 云端识别数据流（含安全控制）

```
选图/拍照(picker URI)
  → 确认云端同意(首次弹出说明，同意写 Preferences)
  → 读取图片 → 缩放/压缩 → base64(内存)
  → POST {baseUrl}/chat/completions（Authorization: Bearer <apiKey>）
  → 解析结果 → 用户确认 → 入账
  → 图片数据释放，不留副本
```

## 4. 待办 / 后续增强

- 缩略图：如后续需要，做成设置项，默认关闭，且仅在用户开启后于沙箱内保存。
- 网络传输：建议服务商地址使用 HTTPS（`base_url_placeholder` 已引导 https 示例）。
- API Key：建议接入系统级安全存储（KeyStore/HUKS）替代明文 Preferences（需确认目标 API 版本支持）。
- 崩溃日志：确认 `.gitignore` 生效并清理仓库根目录历史 `jscrash-*.txt` 文件。
