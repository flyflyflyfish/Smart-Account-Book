# 大模型辅助开发（vibecoding）经验

> 本文记录团队在本项目中使用大模型的方式、原则与经验。
>
> 状态：草稿。第 3.3 节的提示词细节、第 4、5 节需要两名成员根据真实经历补充；没有发生过的事不要写。

## 1. 实际工作流与使用范围

本项目的代码几乎全部由大模型编写，人负责派活、验证和把关。

| 环节 | 使用的工具 | 做什么 |
| ---- | ---------- | ------ |
| 总体分析与提示词起草 | Claude | 先分析整体需求，再起草分步骤的提示词 |
| 编码实现 | DevEco Code（终端 agent）中的 GLM5.3 | 按提示词一块一块实现，几乎所有代码由它完成；选它的原因是在 DevEco Code 里可以免费使用 |
| 验证 | 真机运行 | 人在真机上操作应用，发现问题 |
| 缺陷修复 | 同一个 agent | 人把现象反馈给 agent，由它自己定位并修复 |
| 测试与文档 | 待补充 | 待补充是否同样由 agent 完成，以及人做了哪些审查 |

## 2. 工作原则

以下原则来自开题报告：

1. 先给设计约束与接口，再让模型生成实现；
2. 生成的代码必须经过人工审查与测试验证后才能提交；
3. 保留关键提示词和迭代过程，记录"如何用好"的经验。

实际做法是"两段式"：让对话能力强的模型先做整体分析并写好提示词，再把提示词拆成小步骤交给执行 agent，每一步完成后在真机上验证，再进入下一步。

## 3. 案例

### 3.1 案例记录模板

每个案例按下面四项写，便于展示时讲清楚：

- **目标**：想让模型做什么
- **怎么问的**：关键提示词或给了哪些约束
- **哪里出了问题**：模型的输出错在哪里、是怎么发现的
- **如何纠正**：人工做了什么，最后怎么验证的

### 3.2 案例：课设交付物的准备（2026-11-05，使用 Claude）

这个案例是本次整理交付物时发生的，记录者当时就在场。

- **目标**：对照课设评分表，找出仓库缺口并补齐。
- **做法**：让 Claude 读取仓库的分支、提交、PR、issue、CI、`scripts/` 与 docs 目录，对照评分表逐条核对；再由 Claude 创建 issue、通过分支和 PR 提交改动。
- **发现的问题**（均为实测）：此前 PR 与 issue 均为 0；`scripts/` 下没有部署与 demo 脚本；KPI 文档缺少分配方式，且伍翰彬的行数为空；CONTRIBUTING 中的分支名与实际不符。
- **Claude 自己的验证**：格式检查脚本和运行脚本，在临时 git 仓库中用构造的正反例跑过（行尾空格、Tab、缺换行、CRLF、Markdown 豁免、参数错误、回退逻辑）；伍翰彬的行数通过 GitHub 提交接口逐条核对，与原文档合计一致。
- **没有验证的部分**：CI 在 GitHub 上的实际运行、`pre-commit install` 的真实流程、`devecocli build` 命令本身。Claude 没有 DevEco 环境，也无法运行 HarmonyOS 应用，这些必须由人在真机或 IDE 上确认，PR 描述中已逐项写明。
- **必须由人做的部分**：分配结果由两人协商决定，Claude 没有代填；伍翰彬自己的工作量不能由 Claude 代做，只能由他写测试、开 issue、做评审。
- **体会**：让 Claude 先"审计"再"动手"，比直接让它"补齐所有内容"可靠得多；同时一定要让它写明哪些没验证过。

### 3.3 来自提交历史的案例

下面几处在提交说明中有明确记录。这两个缺陷的来源与处理方式如下：它们是 agent 写出来的缺陷，在真机上暴露，由同一个 agent 自己修复。提示词的具体内容待补充。

1. **真机批量删除必败**（多账本提交）：`RdbPredicates.in` 在真机上抛出参数错误，改为循环单删。
   - 怎么问的：按分步提示词派活，具体提示词待补充
   - 哪里出了问题：agent 写的实现在真机上报错，模拟结果不能代替真机
   - 如何纠正与验证：人在真机上发现并反馈现象，agent 自行定位并修复，改动后在真机上验证
2. **切主题后小组件卡片变棕**（桌面小组件重构提交）：主应用与卡片进程的 preferences 缓存实例互不可见，读写前需要重新加载。
   - 怎么问的：按分步提示词派活，具体提示词待补充
   - 哪里出了问题：跨进程的缓存可见性问题，只有在真机上切换主题才会出现
   - 如何纠正与验证：人在真机上发现并反馈现象，agent 排查出原因并修复，提交说明中记录了根因
3. **识别后处理的三个方向最终不落地**（v7 收尾提交）：经成对复核，三个方向均无净收益，训练侧代码已回退。
   - 这个案例的价值在于"用数据否决了方案"：待补充当时是谁提出的方向、如何设计复核
